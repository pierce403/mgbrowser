## Beacon API, WebIDL Method Overrides, Navigation Timing, Annex B & Google Search Fallback (`v0.9.31`)

### Intent & Root-Cause Investigation

- Investigated user-reported console errors when searching on `https://www.google.com/` (`https://www.google.com/search?hl=en&source=hp&biw=&bih=&gbv=2&q=ninjas&btnG=Google+Search`):
  1. `[ERR JS] JavaScript: Inline script 4: TypeError: Setting DOM property sendBeacon is not implemented`
  2. `[ERR JS] JavaScript: Timer callback: TypeError: not a callable function`
- Root causes identified:
  1. `navigator.sendBeacon` was not implemented, AND Proxy `set` in `crates/mg-sparkle/src/js_browser/boa.rs` only permitted own-property writes on `node:*`/`document`/`subdoc:*`/`event:*` while treating callable WebIDL operations as read-only attributes — causing Script 4's `typeof navigator.sendBeacon!=="function"&&(navigator.sendBeacon=function(a){(new Image).src=a})` and `/httpservice/retry/enablejs` Script 2 to throw `TypeError: Setting DOM property sendBeacon is not implemented`, followed 2 seconds later by Script 5's `setTimeout(..., 2000)` throwing `TypeError: not a callable function` on `navigator.sendBeacon(...)`.
  2. SearchGuard scripts also probe `String.prototype.substr` (omitted when `boa_engine` is built without `annex-b`), `performance.timing.navigationStart` / `responseStart`, `performance.navigation.type`, and `iframe.contentWindow.String`.
  3. With `navigator.sendBeacon` present, SearchGuard's `knitsail` BotGuard bytecode VM executes `~46.94M` Boa opcodes and hits cooperative `OPCODE_LIMIT = 1_000_000` (`RealmState::Fatal` at `60.5 MiB / 64.0 MiB` cumulative worker allocations) before Script 5 can unhide `#yvlrue`, which would otherwise project `0` visible items instead of the page's `<noscript>` fallback and `<meta http-equiv="refresh">` to `/httpservice/retry/enablejs`.

### Decisions & Implementation

- Implemented W3C Beacon `navigator.sendBeacon(url, data?)` (`<= 64 KiB` HTTP/HTTPS validation across `USVString`, `URLSearchParams`, and `BufferSource`), standard read-only `Navigator` properties, `performance.timing` & `performance.navigation`, and Annex B `String.prototype.substr`, `trimLeft`/`trimRight`, and `Date.prototype.toGMTString` in `crates/mg-sparkle/src/js_browser/boa/web_apis.rs`.
- Updated Host Proxy `get` and `set` in `crates/mg-sparkle/src/js_browser/boa.rs` so WebIDL operations and expandos are writable/overridable on host wrappers (except `[LegacyUnforgeable]` `location` and `dataset:*` invalid names) while read-only IDL data attributes (`navigator.userAgent`, `navigator.webdriver`, `document.nodeType`, etc.) remain non-writable and `Object.defineProperty` wrapper invariants stay unchanged.
- Populated same-origin `iframe.contentWindow` in `crates/mg-sparkle/src/js_browser/boa/dom_ops.rs` with standard JS constructors and platform globals.
- Updated `crates/mg-chassis/src/lib.rs` so when initial scripts hit `RealmState::Fatal` with an empty rendered item list (`doc.items.is_empty()`) and `<noscript>` provides fallback items or `<meta http-equiv="refresh">`, `App` adopts the `<noscript>` fallback projection while preserving `InitialScriptOutcome` diagnostics and `ScriptWorkStatus::Blocked`.
- Added unit and integration regression coverage in `crates/mg-sparkle/tests/real_site_compat.rs` (`google_search_send_beacon_method_override_timing_substr_and_iframe_intrinsics_work`) and `crates/mg-chassis/src/lib.rs` (`fatal_initial_script_with_empty_projection_falls_back_to_noscript`).

## Live Google Search End-to-End Parity, Strict `<noscript>` Suppression, Sloppy Direct-`eval` Fix & WebIDL Completion (`v0.9.32`)

### Intent & Root-Cause Analysis ("Why These Were Missed")

- User reported seeing `"Turn on JavaScript to keep searching / The browser you're using has JavaScript turned off"` on `v0.9.31` when running a Google search, and asked us to fix it and ensure nothing else like this is missed.
- Five root causes were identified and systematically eliminated:
  1. **False `<noscript>` activation (`crates/mg-chassis/src/lib.rs`)**: `v0.9.31`'s fallback projected `<noscript>` items and followed `<noscript><meta http-equiv="refresh" content="0;url=/httpservice/retry/enablejs">` whenever initial scripts hit `RealmState::Fatal` (`OPCODE_LIMIT = 1_000_000`). Per HTML §4.12.2, `<noscript>` must NEVER be active when `scripts_enabled == true`; activating `<noscript>` actively tricked Google into serving its `"Turn on JavaScript"` error page.
  2. **Worker resource profile ceiling on interactive challenge pages**: Google's `knitsail` SearchGuard challenge executes `~24.5M–24.9M` Boa opcodes across `~221–228` dynamic `eval`/`Function` admissions and `~231 MiB` cumulative requested allocations (`~13.3 MiB` peak live heap), exceeding the narrow `1M`-opcode / `64 MiB`-cumulative CI research profile (`boa-page-process-v1`).
  3. **Upstream `boa_engine 0.22.0` sloppy direct-`eval` dynamic-slot leak (`vendor/boa_engine-0.22.0/`)**: When `knitsail` repeatedly invoked a VM step function containing sloppy direct `eval("var ...")`, `analyze_scope_eval` appended bindings to the shared `CodeBlock`'s compile-time `Scope`. Subsequent calls created `FunctionEnvironment` with `deleted_bindings = false` for those dynamic `eval` slots and checked a stale pre-lookup `is_global` flag in `GetNameOrUndefined` (`typeof`) — silently corrupting outer variable lookups and causing ~50% of cold SearchGuard runs to abort early at `~143` admissions (`HTTP 429`) instead of completing `~222` admissions (`HTTP 200`).
  4. **WebIDL prototype, brand, event, image & `Window` surface gaps (`crates/mg-sparkle/src/js_browser/boa/`)**: SearchGuard's telemetry and anti-automation probes inspect `Object.getPrototypeOf(window) === Window.prototype`, `Navigator.prototype` (`webdriver` getter descriptor + brand check, `PluginArray`, `MimeTypeArray`), `HTMLIFrameElement.prototype.contentWindow`, `HTMLMediaElement`, `HTMLImageElement` (`naturalWidth`, `complete`, `decode`, etc.), 42 `Window` properties/methods, and `MouseEvent` coordinate/modifier properties, and required modern handles (`navigator`, `history`, `mevent:*`, `subdoc:*`, `abortsignal:*`, `xhr:*`) never to fall through to `host.get` (`TypeError: Invalid DOM handle`).
  5. **SERP inline `data:image/` size (`<= 77 KiB`) & worker layout geometry (`crates/mg-sparkle/`)**: Google's `gbv=2` SERP injects `19` inline base64 `data:image/` maps and thumbnails up to `77,054` bytes (exceeding the old `4,096`-byte attribute cap), wraps organic result `<h3>` headings inside `Display::Inline` `<a>` elements, and requires the full `2,000,000`-step layout budget in `styled_layout::compute_boxes` so `getBoundingClientRect()` and native click hit-testing resolve `624x23` link boxes instead of `0x0`.

### Implementation & Prevention Guards

- Removed `<noscript>` / `<meta http-equiv="refresh">` fallback activation when `scripts_enabled == true` in `crates/mg-chassis/src/lib.rs`, guarded by `fatal_initial_script_never_activates_noscript_or_meta_refresh`.
- Vendored `boa_engine 0.22.0` in `vendor/boa_engine-0.22.0/` with `[patch.crates-io]`, reserving static `function_scope_bindings` in `CodeBlock`, marking post-compile dynamic `eval` slots deleted-until-declared in `FunctionEnvironment::new`, skipping deleted outer-scope bindings in `find_runtime_binding`, and checking `binding_locator.is_global()` after `find_runtime_binding` in `GetNameOrUndefined`, guarded by `sloppy_direct_eval_dynamic_var_bindings_stay_isolated_across_repeated_calls`.
- Completed branded `Window`, `Navigator`, `HTMLIFrameElement`, `HTMLMediaElement`, `HTMLImageElement`, `Element`/`Node`, and `MouseEvent`/`UIEvent` WebIDL prototypes/descriptors/methods across `boa.rs`, `dom_events.rs`, `dom_ops.rs`, and `web_apis.rs`, guarded by automated WebIDL surface audits (`webidl_window_navigator_iframe_and_media_prototypes_enforce_brand_and_descriptors` and `webidl_window_mouse_event_and_image_surface_covers_audited_properties`).
- Raised `data:image/` `src` attribute and inline materialization caps to `256 KiB` (`<= 8` large inline images, `<= 1 MiB` total) in `document.rs` and `js_browser.rs`, and aligned `styled_layout::compute_boxes` (`2,000,000` budget) + `geometry_style` (`Display::Inline` descendant unions, `64`-sheet cap, readable-flow fallback), guarded by `large_data_image_attribute_materializes_inline_image_resource`, `styled_inline_anchor_wrapping_heading_exposes_non_zero_bounding_client_rect`, and `worker_layout_cache_handles_over_sixty_four_inline_stylesheets_without_zero_rects`.
- Added `ResourceProfile::InteractivePageV1` (`boa-interactive-page-v1`: `32M` opcodes, `16 MiB` source, `64/512 MiB` worker memory, `5 CPU s`, `768 MiB` `RLIMIT_AS`, `10 s` active time) for interactive desktop launches while preserving `boa-page-process-v1` unchanged across all library defaults, worker selftests, WPT runners, and CI gates.
- Verified `4/4` consecutive cold live SearchGuard runs (`HTTP 200`, `181 KiB` SERP) and full live X11 + Playwright `https://www.google.com/` -> search `ninjas` -> `ninjas - Google Search` (`176` items, `19` inline `data:image/` resources, Portland Places map rendered) -> click first organic result -> `https://en.wikipedia.org/wiki/Ninja` (`2,644` items) with `0` JS errors and `0` CSS/image warnings.
