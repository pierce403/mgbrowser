## Beacon API, WebIDL Method Overrides, Navigation Timing, Annex B & Google Search Fallback (`v0.9.31`)

### Intent & Root-Cause Investigation

- Investigated user-reported console errors when searching on `https://www.google.com/` (`https://www.google.com/search?hl=en&source=hp&biw=&bih=&gbv=2&q=ninjas&btnG=Google+Search`):
  1. `[ERR JS] JavaScript: Inline script 4: TypeError: Setting DOM property sendBeacon is not implemented`
  2. `[ERR JS] JavaScript: Timer callback: TypeError: not a callable function`
- Root causes identified:
  1. `navigator.sendBeacon` was not implemented, AND Proxy `set` in `crates/mg-sparkle/src/js_browser/boa.rs` only permitted own-property writes on `node:*`/`document`/`subdoc:*`/`event:*` while treating callable WebIDL operations as read-only attributes — causing Script 4's `typeof navigator.sendBeacon!=="function"&&(navigator.sendBeacon=function(a){(new Image).src=a})` and `/httpservice/retry/enablejs` Script 2 to throw `TypeError: Setting DOM property sendBeacon is not implemented`, followed 2 seconds later by Script 5's `setTimeout(..., 2000)` throwing `TypeError: not a callable function` on `navigator.sendBeacon(...)`.
  2. SearchGuard scripts also probe `String.prototype.substr` (omitted when `boa_engine` is built without `annex-b`), `performance.timing.navigationStart` / `responseStart`, `performance.navigation.type`, and `iframe.contentWindow.String`.
  3. With `navigator.sendBeacon` present, SearchGuard's `knitsail` BotGuard bytecode VM executes `~46.94M` Boa opcodes and hits cooperative `OPCODE_LIMIT = 1_000_000` (`RealmState::Fatal` at `60.5 MiB / 64.0 MiB` cumulative worker allocations) before Script 5 can unhide `#yvlrue`, which would otherwise project `0` visible items instead of the page's `<noscript>` fallback and `<meta http-equiv="refresh">` to `/httpservice/retry/enablejs`.

### Decisions & Implementation

- Implemented W3C Beacon `navigator.sendBeacon(url, data?)` (`<= 64 KiB` HTTP/HTTPS validation across `USVString`, `URLSearchParams`, and `BufferSource`), standard read-only `Navigator` properties, `performance.timing` & `performance.navigation`, and Annex B `String.prototype.substr`, `trimLeft`/`trimRight`, and `Date.prototype.toGMTString` in `crates/mg-sparkle/src/js_browser/boa/web_apis.rs`.
- Updated Host Proxy `get` and `set` in `crates/mg-sparkle/src/js_browser/boa.rs` so WebIDL operations and expandos are writable/overridable on host wrappers (except `[LegacyUnforgeable]` `location` and `dataset:*` invalid names) while read-only IDL data attributes (`navigator.userAgent`, `navigator.webdriver`, `document.nodeType`, etc.) remain non-writable and `Object.defineProperty` wrapper invariants stay unchanged.
- Populated same-origin `iframe.contentWindow` in `crates/mg-sparkle/src/js_browser/boa/dom_ops.rs` with standard JS constructors and platform globals.
- Updated `crates/mg-chassis/src/lib.rs` so when initial scripts hit `RealmState::Fatal` with an empty rendered item list (`doc.items.is_empty()`) and `<noscript>` provides fallback items or `<meta http-equiv="refresh">`, `App` adopts the `<noscript>` fallback projection while preserving `InitialScriptOutcome` diagnostics and `ScriptWorkStatus::Blocked`.
- Added unit and integration regression coverage in `crates/mg-sparkle/tests/real_site_compat.rs` (`google_search_send_beacon_method_override_timing_substr_and_iframe_intrinsics_work`) and `crates/mg-chassis/src/lib.rs` (`fatal_initial_script_with_empty_projection_falls_back_to_noscript`).
