### Findings and bounded implementation (`v0.9.34`)

- **Pure-Rust WebP image decoding & interactive oversize downscaling
  (`crates/mg-sparkle/src/images.rs`, `docs/DEPENDENCIES.md`)**:
  - Enabled the pure-Rust `webp` feature on `image = 0.25.10` (`image-webp = 0.2.4`,
    `byteorder-lite = 0.1.0`, `quick-error = 2.0.1`; zero `libwebp` or C/C++
    bindings; verified via `tmp/check-dependencies` and JSPLAN dependency audit).
  - Added `RIFF....WEBP` magic-byte header sniffing across `application/binary`
    and `application/octet-stream` CDN responses (fixing live Google News story
    thumbnails and publisher favicons) and proportional downscaling in
    interactive mode into `<= 2048` px per side / `<= 1,048,576` decoded pixels
    while keeping non-interactive oversize rejection unchanged.
- **CSS `mask-image` / `-webkit-mask`, dropdown containment & form controls
  (`crates/mg-sparkle/src/document.rs`, `style.rs`, `styled_layout.rs`)**:
  - Added CSS `mask-image` / `-webkit-mask` (`url(...)`, position, size, repeat)
    alpha-channel tinting for monochrome UI icons (Wikipedia Vector 2022, GitHub
    Primer, Bing), nested `<li>` dropdown subtree hiding, `<input placeholder>`
    text painting, author-styled `<button>` borders/backgrounds, and strict
    HTML/XML attribute-key validation matching arena projection.
  - Raised interactive `<link rel="stylesheet">` discovery across `<head>` and
    `<body>` from `16` to `64` stylesheets with an `8 MiB` Stylo CSS input
    ceiling (`16` sheets and `2 MiB` unchanged in non-interactive mode).
- **Subresource policy, SRI, CORS `fetch`/XHR & cross-origin HTTPS ES modules
  (`crates/mg-chassis/src/net.rs`, `resources.rs`, `scripts.rs`, `lib.rs`,
  `crates/mg-sparkle/src/js_browser/boa/esm.rs`, `boa.rs`, `js_browser.rs`)**:
  - Added `Policy::for_mode(true)` (`64` stylesheets, `192` subresource
    requests, `4 MiB` per-image/font, `8 MiB` per-stylesheet, `16 MiB` decoded
    script response body via `MAX_RESOURCE_BODY = 16 MiB` in
    `Session::fetch_resource` while keeping `MAX_BODY = 8 MiB` for top-level
    HTML and updater archives, `48 MiB` aggregate bytes, `20 s` deadline) and
    Subresource Integrity (`sha256`/`sha384`/`sha512`) verification.
  - Enabled credential-free cross-origin HTTPS `<script type="module">` fetching
    and module-specifier graph resolution under `InteractivePageV1`. Replaced
    the naive quote scanner in `extract_static_module_specifiers` with
    regex-literal-aware `esm::extract_module_dependencies`, fixing minified
    regex `/\{/` masking that previously hid GitHub's `primer-react` CDN module
    dependency.
  - Enforced credential-free CORS (`Access-Control-Allow-Origin: *` or exact
    caller origin; credentialed cross-origin requests remain denied) for
    `fetch()` and `XMLHttpRequest` in the parent network broker.
- **Interactive Boa worker profile, `DocumentType` / `Intl` globals & CDP event
  backpressure (`crates/mg-butane/src/modern.rs`, `crates/mg-sparkle/src/js_browser/`,
  `crates/mg-chassis/src/cdp.rs`, `src/platform/`, `docs/BOA.md`)**:
  - Scaled `boa-interactive-page-v1` (`32,000,000` opcodes per dispatch,
    `16 MiB` per script / `32 MiB` cumulative source, `384` recursion /
    `262,144` VM stack slots, `16 MiB` `ArrayBuffer`, `48 MiB` DOM logical byte
    admission in both script execution and `BrowserHost::validate_input`,
    `384 MiB` outstanding / `4 GiB` cumulative worker allocation, `2,560 MiB`
    `RLIMIT_AS`, `30 CPU s`, `30 s` active wall, `256` transactions / `128 MiB`
    wire) with identical seccomp, `RLIMIT_NOFILE = 3`, and `RLIMIT_FSIZE = 0`
    confinement. `boa-page-process-v1` remains 100% unchanged.
  - Installed `window.DocumentType` and baseline ECMA-402 `window.Intl`
    (`DateTimeFormat`, `NumberFormat`, `Collator`, `PluralRules`,
    `RelativeTimeFormat`, `ListFormat`, `DisplayNames`, `Segmenter`, `Locale`,
    `getCanonicalLocales`, `supportedValuesOf`), eliminating runtime
    `ReferenceError` aborts on DuckDuckGo's search client bundles.
  - Added synthetic `keydown`/`keypress`/`keyup` dispatch and single-text-input
    `<form>` `Enter` submission, and expanded the outbound CDP WebSocket event
    channel from `256` to `4,096` slots (`MAX_QUEUED_BYTES = 16 MiB` unchanged)
    so bursty `Network.*` events on media-heavy portals never disconnect
    Playwright clients.
  - Moved `canvas_and_observers`, `m2_dom_platform`, `real_site_compat`, and
    `visual_parity` integration tests from `crates/mg-sparkle/tests/` to
    workspace-root `tests/` so WPT Window `source_paths()` stays within its
    unchanged `8,609,615`-byte ceiling (`8,604,526` bytes).
