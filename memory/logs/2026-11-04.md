# 2026-11-04 Work Log

## Google News rounded scrolling and font base correction (v0.9.33)

The user supplied a scrolled Google News screenshot with oversized rounded
search/sign-in backgrounds, long vertical metadata marks, and unintended italic
text. Work is limited to those generic rendering defects; F-025 remains open.

### Findings and implementation

- `RoundedRect::to_physical` subtracted the scroll offset from its top edge but
  not its bottom edge. Every rounded decoration/mask grew by the scroll offset,
  explaining both large header backgrounds and stretched 3px separator dots.
  Both edges now use the same document-to-viewport translation.
- Google's actual Google Sans Text sheet declares italic 400/500/700 before
  normal 400/500/700. The old first-family registration used italic bytes for
  ordinary text. The loader and painter now select a matching normal base
  nearest weight 400, preserving Unicode filtering and all existing caps.
  Selection remains per stylesheet and one face per family. Full face matching,
  variable-font instance selection, and Unicode-subset merging are not added;
  italic-only downloaded families use the existing fallback path.
- No new dependency, resource profile, networking capability, or site-specific
  CSS override is introduced. Workspace/research lock versions and dependency
  inventories are synchronized to 0.9.33.

### Reproduction and focused evidence

- `cargo test --locked --test rounded_scroll`: the old transform fails both
  new pixel tests; restored candidate passes both. Cases cover fixed controls at
  scroll 64/338/600 and scale 1/1.35/2, and translated rounded overflow clipping.
  Before/after logs remain under ignored `tmp/news/`.
- `cargo test --locked --test font_face_bases`: both new tests pass. They cover
  italic-first normal-text pixel parity, normal weight preference, Unicode
  filtering, a 16-family cap, replacement after the cap, and italic-only fallback.
- Actual saved Google News HTML was compared with Chromium headless-shell 142
  at 1280x800 and 1024x768, including scroll 600, with scripts/network blocked
  and an identical DejaVu Sans override. Search is 48px tall and sign-in 40px;
  header overlap and separator streaks are gone. The same-input images were
  visually inspected. This comparison omits fetched thumbnails/fonts; minor
  spacing/placeholder and script-dependent differences remain. It is not fresh
  live-site acceptance or full F-025 completion.
- A fresh candidate headless load could not resolve `news.google.com` in this
  runtime (`Temporary failure in name resolution`). Curl can capture through
  the host's managed proxy, while the browser uses direct transport. No DNS,
  TLS, proxy, or browser policy was changed to conceal that failure.
- Native helper setup also encounters host restrictions on Unix-domain sockets.
  A TCP-only Xvfb is available for local tests; unchanged helpers that require
  their own Unix display cannot be claimed passed here.
