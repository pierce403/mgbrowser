Read the MVP plan ↗Help build it
The browser is running—and now accepts CDP automation. It loads HTML over HTTPS, draws text, submits forms and follows links. An external Rust client can inspect the DOM, type a search, click a result and capture a screenshot through our initial Chrome DevTools Protocol subset. Google’s homepage loads, but its search results require JavaScript that we have not implemented yet. The full Google journey remains open.

01 / The engine

Own the path from bytes to pixels.

Our own HTML parser, document tree, CSS cascade, layout and painting, written in Rust. The proposed first release is a Linux browser for static pages: readable text, images, links and navigation.

Experimental TLS with rustls-rustcrypto. Rust font processing and PNG decoding, with no native library fallback. We prefer an unsupported image to a C binding. JavaScript and broad web compatibility follow later.

02 / The research loop

Make progress reproducible.

State a hypothesis. Make a focused change. Run a fixed corpus. Keep the evidence. Correctness comes before performance, and every result should be reproducible by another contributor.

The planned harness gives humans and agents the same evaluation contract, with bounded runs and review before merging. Our experiments can also help uncover bugs in the Rust libraries we build on.

03 / The route to MVP

First a page. Then a browser.

  1. Native Rust window, document flow, forms and links: working locally.
  2. Initial CDP discovery, navigation, DOM, input and screenshots: verified with an external client.
  3. Next: our JavaScript engine and page integration for Google search.
  4. Expand CSS, images, protocol coverage and repeatable evaluation; validate and release the research MVP.
